```
data/
├── cicids2017/    <- put the real CIC-IDS2017 CSV files here (not committed)
└── demo/          <- auto-generated synthetic demo dataset (clearly labelled)
```

## 1. CIC-IDS2017 (the real labelled dataset)

**What it is.** CIC-IDS2017 is a labelled *network* intrusion-detection dataset
published by the Canadian Institute for Cybersecurity (University of New
Brunswick). It contains five days of captured traffic with labelled benign
activity and attacks (DoS, DDoS, port scan, brute force, botnet, web attacks,
infiltration), distributed both as PCAPs and as CSV files of **flow features**
extracted with CICFlowMeter.

**What it is NOT.** CIC-IDS2017 is **not** an 802.11 / Wi-Fi-specific dataset.
It is captured on a wired-style network testbed and its features describe
IP/TCP/UDP *flows*, not 802.11 management or control frames. Wi-Fi-specific
datasets are **AWID** and **AWID3** (Kolias et al. 2016; Chatzoglou et al.
2021), which contain 802.11 frame-level features such as deauthentication and
evil-twin attacks. NetHawk's feature layer is written so an AWID3 adapter can
be added later without touching the rest of the pipeline.

### Download

1. Go to <https://www.unb.ca/cic/datasets/ids-2017.html> and accept the terms.
2. Download `MachineLearningCSV.zip` (the CSV / `MachineLearningCVE` folder,
   roughly 220 MB compressed).
3. Unzip it and copy the eight `*.pcap_ISCX.csv` files into `data/cicids2017/`:

```
data/cicids2017/
├── Monday-WorkingHours.pcap_ISCX.csv
├── Tuesday-WorkingHours.pcap_ISCX.csv
├── Wednesday-workingHours.pcap_ISCX.csv
├── Thursday-WorkingHours-Morning-WebAttacks.pcap_ISCX.csv
├── Thursday-WorkingHours-Afternoon-Infilteration.pcap_ISCX.csv
├── Friday-WorkingHours-Morning.pcap_ISCX.csv
├── Friday-WorkingHours-Afternoon-PortScan.pcap_ISCX.csv
└── Friday-WorkingHours-Afternoon-DDos.pcap_ISCX.csv
```

4. Retrain:

```bash
python scripts/train_model.py
```

The loader accepts any subset of those files — one file is enough to train on
real data. It handles the quirks of the real CSVs automatically: padded column
names (`" Flow Duration"`), `Infinity`/`NaN` values in the rate columns,
latin-1 encoded labels (`Web Attack – Brute Force`), and extra columns NetHawk
does not use.

You can also point NetHawk at the files without copying them:

```bash
export NETHAWK_CICIDS_DIR=/path/to/MachineLearningCVE
python scripts/train_model.py
```

## 2. `demo/nethawk_demo_traffic.csv` — SYNTHETIC DEMO DATA

Generated by `src/nethawk/datasets/synthetic.py`. **This is not real captured
traffic and not CIC-IDS2017.** It is a small, reproducible, labelled dataset in
exactly the same 27-feature schema, so the whole pipeline can be trained and
demonstrated on a laptop with no dataset downloaded.

Any accuracy figure measured on this file describes the demo generator, **not**
real-world intrusion detection. `models/metrics.json` records which data the
current model was trained on (`data_source`), and the dashboard shows a
`MODEL: DEMO DATA` badge whenever a demo-trained model is loaded.

Regenerate it with:

```bash
python scripts/prepare_dataset.py --make-demo --rows 1500
```

## 3. AWID / AWID3 (future work)

Not bundled. To integrate it, add an `AwidFeatureAdapter` next to the existing
adapters in `src/nethawk/features/adapters.py` and extend the rules in
`src/nethawk/detection/classifier.py` with the 802.11 attack labels
(deauthentication, disassociation, evil twin, krack). The ML, risk, decision,
database and dashboard layers need no changes.
